Words and output
================

The idea reaches the *words a person reads*, not only the structure. These are the rules for them, each from a defect.

One place for every sentence
----------------------------

A sentence a person reads is written once, in the layer that owns it, and used by every surface. "There are no restore points yet" was told
three times in three layers, in different words, and the window's version was the only one that did not say what to do about it. It is one
constant in the core now, used by the window, the listing and the restore command.

Say what to do next
-------------------

Wherever nothing is there, or something failed, say what to do about it. A first snapshot ends with the restore point's name and the command that puts
every area back to it. A refusal because there is no terminal says exactly which flag to pass. A mistyped area is answered with the ones that exist.

One voice for failure
---------------------

``Could not <what>: <why>``, built by one function. The window had worded failure seven ways (six of one shape and one odd); a new failure can no longer be
worded differently by accident.

Counts: one, many, none
-----------------------

- A plural is said by a helper (``counted(n, "snapshot")``), never spelled by hand. The agreement of a word with a number that is not shown has its own helper
  (``by_number(n, "includes", "include")``).
- None is *no snapshots*, not *0 snapshots*.
- A **length of time keeps its zero**: *0 seconds* is right and *no seconds* is not (a test said so when the helper first said "no" for everything).
- Do not leave a plural to the reader (``snapshot(s)``). A guard counts that form inside strings.
- Test the **singular and the zero**, not only the plural. A change that read correctly for "3 of 8" said "its 1 snapshots" for one.

Say only what happens
---------------------

A preview that listed *0 reverted, 1 removed, 0 brought back* spent two of its three numbers saying nothing. Build the sentence from the non-empty parts
(*1 removed*, or *no change*), in one function in the core, used by every place that says it.

Stdout is for scripts, stderr is for people
-------------------------------------------

What a script reads from standard output stays what it was. A hint to a person goes to standard error, only when standard error is a terminal and
the output is not JSON, and it **obeys the option that silences hints**. Check both: once in a pseudo-terminal (the person sees it) and once piped (the script
does not). A hint that ignored its own switch was found by reading the option's documentation.

No tool words above the adapter
-------------------------------

The words of the underlying tools stay in the adapter that drives them. A person-facing sentence says *area*, *snapshot*, *restore point*, never the tool's own word
unexplained. When a pair of snapshots is shown, say *before* and *after #3*, and explain the pair once in the help, in the same row as the list it describes, because the
help page fits a small terminal exactly and an extra entry made it overflow (two tests existed for exactly this).

Retiring a word
---------------

When a word is wrong (here, *config* for what a person calls an *area*):

1. Rename its uses with a **lexer-based** tool that follows the name inside string interpolation and verifies that no string literal changed.
2. Add a guard: the word is not an identifier outside the one adapter that owns it. Use a lexer for the guard too.
3. Search the strings that remain for the word, and **read all of the results**. Most are not for a person (JSON keys, a URL, a reference to the tool's own manual page, messages in
   test support); fix the one that is.

Published identities stay
-------------------------

A key in a JSON output, a contract's identity for an argument, a word stored in an old journal: other programs and older files read them. Renaming them for the sake of a word breaks those readers.
Give the person a plain word *beside* the stored one (the journal stores ``command``; the window shows ``command line``), test both, and write the reason down. In ``snapall`` the contract
still keys the area argument as ``config`` for exactly this reason.

Output that other tools read
----------------------------

Pin it. A committed copy of the program's own contract, generated by the program and compared by a test, means a change to a flag's description shows up as a diff. Regenerate the file from
the program, never by hand, and compare *field by field* rather than trusting that the one change you meant is the only one (the committed copy once still said it came from an old version, which the test
rightly ignored).
